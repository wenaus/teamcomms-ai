Notify LLM from your scripts

Use Notify LLM to send a deliberate notification to selected AI sessions. Choose who should consider it and explain why. Ordinary feed posts and alarms do not wake an LLM automatically.

teamcomms-connect --config /path/to/program.json notify-llm /path/to/notification.json

The Python function is teamcomms.connectors.watcher.notify_llm(...). Use your installation's existing authenticated connector configuration; keep its token in the configured private file.

Prepare a notification: recipients, JSON and retries
  1. Use an environment with teamcomms-ai[connectors] installed and an existing connector configuration with messaging permission.
  2. Find the intended AI recipient in Sessions and copy its session UUID.
  3. Save the JSON below as notification.json, replacing the example values with your source event, observation time and selected recipient. Then run the command above.
{
  "source": "your-application:your-installation",
  "event_id": "source-event-123",
  "reason": "The assigned session needs to review this blocked work.",
  "content": "Describe the finding, requested consideration and source link.",
  "audience": {"session_ids": ["REPLACE_WITH_SELECTED_AI_SESSION_UUID"]},
  "observed_at": "2026-09-15T12:00:00+00:00"
}

These six fields are required; topic is optional. Use the source event's timestamp. On a failed or uncertain send, retry the same file: stable source and event IDs prevent duplicate publication. Keep the reason, content, time and audience unchanged on retry.

A delivery receipt confirms transport; acknowledgment confirms model consideration. Sending a notification does not grant permission to take operational action.
